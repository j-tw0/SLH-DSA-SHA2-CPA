# Correlation Power Analysis on SHA-2-Based SLH-DSA

This repository contains curated **analysis code** for the three experimental
settings described in *Correlation Power Analysis on SHA-2-Based SLH-DSA*,
Cryptology ePrint Archive, 2026/2753.

**Paper:** https://eprint.iacr.org/2026/2753  
**Acquisition and firmware:** https://github.com/j-tw0/SLH-DSA-PRF-Capture

**Scope:** non-profiled SHA-256 correlation power analysis of isolated,
address-based PRF measurements for the six SHA2 SLH-DSA parameter sets. It is
**not** a real-time attack against a production signer, nor a dataset release.

## Match to the paper

| Setting | Notebook | Input | Evaluation |
|---|---|---|---|
| Random-address WOTS+/FORS PRFs (Sections 5.2, 6.1–6.2) | `notebooks/01_random_address_cpa.ipynb` | 30 keys × 5,000 traces, per parameter and address type | **Independent conditional stages**: preceding words supplied as correct |
| One signing path (Sections 5.2, 6.4) | `notebooks/02_signature_sequence_cpa.ipynb` | 3 keys × 3 signatures, FORS and WOTS+ analyzed **separately** | **Chained**: recovered words propagated |
| Key-generation WOTS_PRF (Sections 5.2, 6.5) | `notebooks/03_keygen_wots_cpa.ipynb` | 3 keys, one keygen path each | **Chained** compression CPA |

Experiments with pooled signatures, mixed FORS/WOTS traces, hybrid attack
paths, and next-round leakage validation are outside the scope of the
paper-aligned code release and are intentionally omitted.

The manuscript's full **guessing-entropy/rank-versus-trace-count curves**
(Section 6.3), including the penalized joint-candidate ranking, cannot be
recreated from this package alone: corresponding standalone evaluation code
was not identifiable in the three submitted code archives. The paper's exact
reported statistics also need the original measured traces and local key
manifests, which are not released here. Do not label new local experiments as
numerical replication of the published results without revalidation.

## Source naming and backward compatibility

The Python and notebook filenames now describe their responsibility without
repeating the repository title. **Only names and internal imports were
refactored; the CPA leakage models, candidate ranking, data formats, and
stored capture paths were not redesigned.** Update local Python imports or
external scripts that used the older module names. No compatibility aliases
for the retired filenames are included.

## Installation

Requires Python 3.10+; Python 3.11 recommended. All CPA runners process
pre-collected local `.npy`/JSON arrays; **no hardware is required for analysis**.

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
```

NumPy correlation is supported without TensorFlow. TensorFlow can optionally
accelerate correlation if installed with the appropriate system/GPU libraries.

## Input data and secret-handling

The required capture output structures are generated by the separate
[acquisition repository](https://github.com/j-tw0/SLH-DSA-PRF-Capture).
See [DATASET_LAYOUT.md](docs/DATASET_LAYOUT.md) for the exact expected files.

1. Keep original captures **outside this Git repository** (or under ignored `data/`).
2. The runners **read** `shared_secret_seeds.json` locally to check the recovered
   values. The file contains experimental `SK.seed` values: **never commit it**.
3. The copied SHA-256 core previously contained fixed experimental default seeds.
   The public version replaces them with synthetic demonstration values, matching
   the public capture repository's example-key derivation. **These values do
   not match the original experiment.**
4. For compression analysis of captures collected with another `PK.seed`, pass
   the corresponding public seed via `--pk-seed-hex` (or the local notebook
   environment variable `SLH_CPA_PK_SEED_HEX`). The signing notebook runner
   accepts one width per run if you use the same override across conditions.
   Keygen reads `PK.seed` from each saved capture's metadata.
5. Preserve the acquisition dataset's original `.npy`/JSON formats and order.
   Do not invent or replace real trace values.

## How to run

Launch Jupyter from this repository root or from `notebooks/` and open one of:

- `notebooks/01_random_address_cpa.ipynb`
- `notebooks/02_signature_sequence_cpa.ipynb`
- `notebooks/03_keygen_wots_cpa.ipynb`

**Every notebook defaults to `RUN_CPA = False`.** Set the local capture path and
inspect the inventory; then explicitly enable computation.

CLI examples (replace paths with your actual capture folders):

```bash
# Random addresses: conditional independent-stage evaluation
python src/random_address_cpa.py --base /path/to/random-captures --params 128f --kinds fors,wots --seed-ids 0,1,2 --max-traces 5000 --backend numpy --dry-run

# One-signature, one-key-at-a-time chained evaluation
python src/signature_cpa_batch.py --base /path/to/signature-captures --params 128f --source message --seed-ids 0,1,2 --signature-ids 0,1,2 --kinds fors,wots --attacks expansion,compression --protocol chained --dry-run

# Key-generation path chained compression evaluation
python src/keygen_wots_cpa.py --base /path/to/keygen-captures --params 128f --seed-ids 0,1,2 --protocol chained --dry-run
```

Remove `--dry-run` to execute CPA. Large `s` parameter sets can require
substantial RAM, disk, and computation time; choose a small validated condition
first. Keep the analysis output directory separate from input captures.

## Core methods and protocol differences

- SHA-256 compression-round state update `A'` and message-schedule expansion
  targets; cumulative Hamming-weight leakage hypotheses over 8-bit low-to-high
  units with carry propagation and a beam width of 4.
- The 256-bit `W5/W13` joint candidate stage and the 128-bit WOTS+ `W18`
  alternative for recovering `W9` are present in the original shared CPA core.
- **Random-address evaluation:** the included thin adapter calls the existing
  CPA primitives but restores correct preceding words between word-level
  stages. These per-stage conditional successes must not be reported as
  end-to-end recovery rates.
- **Signing/keygen evaluations:** previous *recovered* words are passed on;
  no true preceding values are supplied for candidate ranking.
- The 192/256 WOTS+ **full message-schedule chain** is not claimed as a
  reported result in this paper.

For acquisition assumptions, evaluation protocols, and reproducibility
limitations, see [REPRODUCIBILITY_NOTES.md](docs/REPRODUCIBILITY_NOTES.md).
